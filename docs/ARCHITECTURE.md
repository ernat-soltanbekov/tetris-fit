# Устройство решателя

## Одна фигура, одна ответственность

`tetromino.New` проверяет четыре разные клетки внутри 4×4. Распространение
достижимости через соседей сверху, снизу, слева и справа подтверждает связность.
Диагональное касание не соединяет фигуру. Затем минимальные X и Y вычитаются из
координат: сдвинутые копии получают одинаковое представление.

`parser.Parse` читает не более 1025 байт и проверяет структуру файла, не пытаясь
исправлять ошибочные данные. `ReadFile` предварительно отклоняет каталоги,
устройства, FIFO и слишком большие обычные файлы. `Parse` возвращает ошибки
чтения вызывающему коду. В CLI все ошибки входа превращаются в `ERROR`.

Повороты — четыре преобразования `(x,y) → (3-y,x)` с нормализацией и удалением
дубликатов. O имеет одну ориентацию, I — две, L — четыре. Отражений нет.
У `solver.Options.Rotate` значение `false` сохраняет ориентации; CLI явно
передаёт `true` по умолчанию, в соответствии с официальными тестами задания.

## Поиск на одном квадрате

`Solve` заранее перечисляет положения каждой ориентации, целиком помещающиеся
в квадрат. У положения есть четыре номера клеток для печати и до четырёх
битовых масок строк для проверки пересечения.

`visit` выбирает группу ещё не уложенных фигур. `mostConstrained` проверяет
доступные положения и предпочитает группу с наименьшим числом вариантов.
При пересечении битовых масок положение запрещено. При отсутствии пересечения
`place` занимает четыре клетки, после чего вызывается следующий уровень поиска.
Если продолжение невозможно, `remove` освобождает те же клетки, счётчик откатов
увеличивается, визуализатор получает событие, пробуется следующее положение.

Буква определяется номером фигуры во входе, даже если другая группа размещалась
раньше. Размещение в порядке A, B, C не обязательно для корректной маркировки.

## Почему ускорения не теряют решения

- **Нижняя граница по площади:** квадрат должен вместить `4 × число фигур`
  клеток. Дополнительно проверяются габариты. Поворот не меняет наибольшую сторону
  ограничивающего прямоугольника фигуры, поэтому эта проверка допустима и с поворотами.
- **Прямоугольные фигуры:** для фиксированных горизонтальных I в каждой строке
  помещается не более `floor(N/4)` фигур. Для вертикальных действует тот же довод
  по столбцам. Каждая O занимает по клетке каждого из четырёх цветов
  `(чётность строки, чётность столбца)`, поэтому O не больше `floor(N/2)²`.
  Для поворачиваемых I эта проверка намеренно не применяется.
- **Группировка:** одинаковым фигурам разрешены те же положения, поэтому обмен
  их букв не меняет осуществимость укладки. У каждой группы положения выбираются
  в возрастающем порядке индексов. Любой набор положений можно упорядочить так,
  следовательно, теряются только перестановки одинаковых фигур.
- **Выбор ограниченной группы:** меняет порядок перебора, а не набор допустимых ходов.
  Если свободных положений меньше оставшихся фигур группы, разместить их нельзя.
- **Компоненты пустого пространства:** связная фигура не пересекает две раздельные
  пустые области. Область размера `k` должна оставить хотя бы `k % 4` пустых
  клеток. Если сумма этих остатков больше общего допустимого числа пустых клеток,
  продолжение невозможно. Проверка применяется при не более восьми пустых клетках.
- **Кеш неудач:** ключ включает занятость строк, число использованных фигур
  каждой группы и следующий разрешённый индекс положения. Одна занятость доски
  была бы недостаточным ключом. Запоминаются только полностью исследованные
  неудачи; прерывания не кешируются. После 50 000 записей новые записи не добавляются.

Размеры перебираются по возрастанию. Успех на N означает, что все меньшие размеры
опровергнуты полным перебором или необходимыми геометрическими условиями.
Граница 24×24 конструктивна: сетка из 6×6 отдельных ячеек 4×4 вмещает 26 фигур.

Независимый тестовый решатель использует обычный массив `bool`, порядок входа и
перебор всех якорных клеток. Он не использует группировку, маски, кеш, эвристики
или отсечение областей рабочего решателя. Сравниваются 361 упорядоченная пара
всех 19 фиксированных ориентаций в обоих режимах и 120 наборов из 3–4 фигур:
всего 842 сравнения. Это сильная проверка малых случаев, а не формальное
доказательство корректности программы на всех входах.

## Счётчики, события и остановка

`Attempts` увеличивается непосредственно перед `fits` в `mostConstrained`.
`Backtracks` увеличивается после `remove` при возврате из неудачной ветви.
Они не участвуют в выборе решения; исключение — явно заданный лимит попыток,
который останавливает поиск. Отсечённое состояние без фактического снятия фигуры
само по себе не добавляет откат.

Наблюдатель получает отдельную копию доски после каждого действия. Изменение
этой копии не меняет состояние поиска. Ошибка записи прерывает работу и
возвращается вверх; визуализатор не скрывает потерю вывода. Время вызова
наблюдателя входит в измеренное время решателя.

Отмена контекста проверяется на каждом рекурсивном входе и через каждые 256
проверок положений. Ошибка контекста или лимита возвращает результат без сетки.
Каждый вызов `Solve` владеет своим состоянием; параллельные вызовы не делят
доски, кеши и счётчики. Сами переданные пользовательские callback и writer
должны соблюдать обычные правила доступа вызывающей стороны.

Поиск ограничен временем; запись в произвольный блокирующий `io.Writer` не
может быть насильно прервана средствами этого API. Временная граница относится
к вычислению, а не к неисправному терминалу или зависшей файловой системе.

## Подготовка к разговору с аудитором

Эти примеры объясняют работу. Проверить личное понимание может только живой
разговор; автоматические тесты этого не устанавливают.

1. **Что такое откат?** Поставили фигуру, обнаружили, что оставшиеся уже не
   помещаются, сняли поставленную фигуру и пробуем другое положение.
2. **Как получить теоретический минимум?** Для восьми фигур 32 клетки;
   5×5 мало, 6×6 достаточно по площади, значит нижняя граница — 6.
   Форма фигур всё ещё может потребовать больше места.
3. **Где измеряется работа?** Проверки пересечений — попытки; фактические снятия —
   откаты; `time.Since` измеряет длительность. Можно включить визуализатор и
   проследить каждое увеличение счётчика откатов.
4. **Как получить компактность?** Четыре O в 4×4 дают `16/16 × 100 = 100%`.
   Шесть фигур в 5×5 дают `24/25 × 100 = 96%` и одну пустую клетку.
5. **Что предсказать до запуска?** Одна O требует 2×2, пустых клеток 0.
   Две L из `rotation-demo` с поворотами требуют 3×3, пустых 1;
   в фиксированной ориентации требуют 4×4, пустых 8.

Практическое упражнение: нарисовать следующий ход для `rotation-demo --fixed`,
объяснить, почему он приводит в тупик, а затем сверить предсказание с
`tetris-visualizer`. Изменение одной фигуры во входе даёт новый пример для защиты.
