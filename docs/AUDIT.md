# Карта аудита

Основание: предоставленное ТЗ `tetris-fit__ts.md`, включая раздел AUDIT.
Оригинальные тестовые файлы получены из публичного API Tomorrow School;
их происхождение и контрольные суммы записаны в `testdata/SOURCES.json`.

| Требование | Реализация / проверка |
| --- | --- |
| Структура каталогов из ТЗ | Обе команды `cmd/`, пять требуемых пакетов `internal/`, тесты, `go.mod`, README, все официальные fixtures |
| Go и только стандартные пакеты | `go.mod` без зависимостей; CI проверяет `go list -m all` |
| Успешная компиляция | `make build` собирает обе команды |
| Минимальный квадрат | Возрастающий размер, полный поиск с безопасным отсечением; независимый oracle на 842 наборах |
| Буквы A…Z и сохранение всех фигур | Проверка каждого набора из четырёх координат в unit-тестах и независимом Python-аудите |
| Плохие примеры 00–04 и badformat | Каждый даёт ровно `ERROR\n`, код 1; проверяются обычный режим, анализатор и визуализатор |
| goodexample00 | 2×2, 0 пустых клеток |
| goodexample01 | 5×5, 9 пустых клеток |
| goodexample02 | 4×4, 4 пустые клетки, менее 10 секунд |
| goodexample03 | 5×5, 5 пустых клеток, менее 10 секунд |
| hardexam | 5×5, 1 пустая клетка, менее 10 секунд |
| Анализ качества | `analyzer.Quality`: размер, заполненность, пустоты, компактность, теоретическая граница, совпадение |
| Отдельные вычисления метрик | `GridSize`, `TotalCells`, `FilledCells`, `EmptyCells`, `Compactness`, `TheoreticalMinimum`, `MatchesMinimum` с прямыми тестами |
| Анализ производительности | `analyzer.Performance` принимает реальные counts и `time.Duration`, проверяет их, возвращает измеренные значения |
| Измеренное время | `time.Now` / `time.Since` внутри `Solve`, без выдуманных оценок |
| Отсутствующий файл и ERROR | Ни падения, ни фиктивного итогового отчёта |
| Читаемость и формат | Разделение обязанностей по пакетам, `gofmt`, `go vet`, пояснения геометрических ограничений |
| Тесты parser / solver / analyzer | Модульные тесты, oracle, fuzzing и race detector |
| Бонус: визуализатор | Отдельный бинарник и `--visualize`, доска после каждой установки и каждого снятия, живые счётчики |
| Бонус: скорость | Предвычисление положений, маски, группировка, выбор ограниченной группы, кеш, геометрические границы |
| Устное объяснение и живое предсказание | Материал для подготовки в ARCHITECTURE; эта часть требует личного ответа на аудите |

## Дополнительные проверки отказоустойчивости

- 26 фигур O; 26 I с фиксированной ориентацией; 27 фигур отклоняются.
- Все 19 фиксированных ориентаций, нормализация и отсутствие зеркального отражения.
- LF, CRLF, отсутствие завершающего LF, неверные длины строк, Unicode, NUL, BOM,
  разорванные фигуры, диагональные соединения, неверное число `#`.
- Ограниченное чтение даже бесконечного `io.Reader`, ошибка чтения, пустой файл,
  слишком большой файл, отсутствующий путь, каталог, FIFO.
- Отмена до поиска и во время поиска, уже истёкший deadline, лимит попыток.
- Ошибка наблюдателя на каждом виде события, ошибка writer, изоляция снимков доски.
- События изменяют ровно четыре клетки правильной буквы, каждый откат виден
  и увеличивает счётчик ровно на один.
- 24 параллельных вызова под race detector; 32 запуска бинарника с восемью
  одновременно работающими процессами; одинаковый вход даёт одинаковые счётчики.
- Смешанные наборы от 8 до 26 фигур: корректное решение либо контролируемая
  остановка после 50 000 проверок, без ложного объявления минимальности.
- Два fuzz-теста: устойчивость парсера с round-trip валидных данных и сравнение
  решателя с независимым oracle для случайных пар фигур.

## Интерпретация ТЗ

Входные клетки обозначены `#`, но итоговые заполненные клетки — буквами A…Z,
как требует основной алгоритм. Анализатор считает именно эти буквы.

Подсказка о поворотах подтверждается `goodexample02`: без них официальный
ожидаемый размер недостижим. Поэтому основной режим допускает повороты,
а фиксированные ориентации доступны через `--fixed`. Наборы не подменяются,
решение не выбирается по имени файла, номера примеров не участвуют в алгоритме.

Скорость проверяется измерением и внешним таймаутом 10 секунд для каждого запуска.
Это свидетельство для тестовых наборов, а не гарантия времени для всех возможных
26 фигур. Ограничение общего вычислительного времени — 2 минуты по умолчанию
и не более 5 минут при явном `--timeout`, в духе good practices задания.
