# tetris-fit

[![Audit](https://github.com/ernat-soltanbekov/tetris-fit/actions/workflows/ci.yml/badge.svg)](https://github.com/ernat-soltanbekov/tetris-fit/actions/workflows/ci.yml)

Точный решатель задачи упаковки тетромино на Go: находит наименьший квадрат,
сохраняет обозначения фигур `A`…`Z`, измеряет качество решения и стоимость поиска.
Бонусный визуализатор показывает каждое размещение и каждый откат.
Приложение использует только стандартную библиотеку Go и работает без сети.

Автор и владелец проекта: [Yernat «GhostOfAstana» Soltanbekov](https://github.com/ernat-soltanbekov).
Военное прошлое, ежедневная утренняя практика боевых искусств с 2008 года,
техническое образование и учёба в Tomorrow School задают подход к проекту:
дисциплина, понятные решения и проверяемый результат. Профессиональная цель —
присоединиться к команде Astana Hub МИИЦР РК. Это личный учебный проект.

## Быстрый запуск

Нужен Go 1.25 или новее. Для дополнительных проверок `make audit` нужен Python 3.9+;
для самого приложения Python и сторонние пакеты не нужны.

```sh
git clone https://github.com/ernat-soltanbekov/tetris-fit.git
cd tetris-fit
make build
./bin/tetris-optimizer testdata/hardexam.txt
./bin/tetris-optimizer testdata/hardexam.txt --analyze
./bin/tetris-visualizer testdata/goodexample01.txt --analyze
```

Без `make`:

```sh
go run ./cmd/tetris-optimizer/ testdata/goodexample02.txt --analyze
go run ./cmd/tetris-visualizer/ testdata/rotation-demo.txt --fixed
```

Обычный режим печатает только квадрат и завершающий перевод строки.
Никаких баннеров или персональной информации в машинном выводе нет.
Например, `goodexample00.txt`:

```text
AA
AA
```

## Формат и параметры

Одна фигура — четыре строки по четыре символа `.` или `#`, ровно четыре `#`,
соединённые общими сторонами. Между фигурами ровно одна пустая строка.
Допустимы 1–26 фигур, LF и CRLF, с одним завершающим переводом строки или без него.
Пробелы, BOM, дополнительные пустые строки и любые другие символы отклоняются.
Файл должен быть обычным файлом размером не более 1024 байт; этого достаточно
для 26 фигур даже с CRLF. Каталоги, устройства и FIFO отклоняются.

| Параметр | Назначение |
| --- | --- |
| `--analyze` | Все метрики качества и поиска после найденного решения |
| `--visualize` | Каждый шаг поиска; эквивалент отдельного `tetris-visualizer` |
| `--rotate` | Повороты на 90°, 180°, 270°; это режим по умолчанию |
| `--fixed` | Только перенос фигур, с сохранением исходной ориентации |
| `--timeout 30s` | Лимит поиска; по умолчанию 2 минуты, максимум 5 минут |
| `--max-attempts 50000` | Лимит проверок размещения; `0` снимает этот лимит |
| `--help` | Справка |

Флаги разрешены до и после пути. Для имени, начинающегося с дефиса, используется
`--`, например `./bin/tetris-optimizer --analyze -- -sample.txt`.
`--fixed` и `--rotate` несовместимы; повторные и неизвестные флаги отклоняются.
Фигуры никогда не отражаются зеркально.

**Почему повороты включены:** официальный `goodexample02.txt` содержит три
одинаково ориентированных T. В режиме `--fixed` минимум — 5×5 с 13 пустыми
клетками; с поворотами — 4×4 с 4 пустыми клетками, как требует аудит.
Все пять официальных ожидаемых результатов выполняются в стандартном режиме.
Исходные файлы сохранены без изменений; ссылки и SHA-256 находятся в
[`testdata/SOURCES.json`](testdata/SOURCES.json).

| Код завершения | Результат |
| --- | --- |
| `0` | Найден минимальный квадрат или показана справка |
| `1` | Ошибка файла, данных или вывода |
| `2` | Ошибка аргументов |
| `124` | Поиск остановлен по времени, числу попыток или сигналу |

Ошибочные данные дают ровно `ERROR` в stdout. При прерывании поиска также
выводится `ERROR`, а причина — в stderr. В визуальном режиме до прерывания
могут быть напечатаны уже выполненные шаги. Незавершённый поиск не выдаёт
частичную укладку за минимальное решение и не печатает итоговый анализ.

## Как находится минимум

1. Парсер проверяет формат и связность, переносит каждую фигуру к началу координат.
2. Начальный размер — `ceil(sqrt(4 × количество фигур))`, с учётом габаритов фигур.
3. Для каждого размера решатель пробует допустимые положения фигур. Если ход
   приводит в тупик, снимает последнюю фигуру и продолжает — это backtracking.
4. После полного исчерпания вариантов размер увеличивается. Первое найденное
   решение минимально среди разрешённых перемещений и поворотов.

Ускорения сохраняют полноту поиска: битовые маски строк быстро проверяют
пересечения, одинаковые фигуры группируются, сначала выбирается группа с меньшим
числом доступных положений, повторные неудачные состояния запоминаются.
Дополнительные безопасные границы отсекают недостаток места для прямоугольных
фигур и неподходящие размеры изолированных пустых областей.
Подробности и обоснование — в [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).

Точная упаковка может требовать большого перебора. У проекта есть проверенные
быстрые случаи и ограничение ресурсов, но нет обещания решить любой произвольный
набор за постоянное время. По истечении лимита приложение сообщает об остановке,
не меняя определение минимальности. Максимум 50 000 запоминаемых состояний
ограничивает рост кеша; глубина рекурсии не превышает 26.

## Анализатор и визуализатор

`internal/analyzer` предоставляет `Quality(grid)` и
`Performance(attempts, backtracks, elapsed)`. Вычисления метрик вынесены в
отдельные тестируемые функции. Все значения получены из решения или поиска:

| Метрика | Как измеряется |
| --- | --- |
| Размер | Число строк квадратного результата |
| Заполнено | Число букв `A`…`Z` в результате; входные `#` заменены буквами |
| Пусто | Число `.` |
| Компактность | `заполнено / (размер × размер) × 100%` |
| Теоретический минимум | Целочисленный `ceil(sqrt(4 × число фигур))` |
| Совпадение с минимумом | Сравнение найденного размера с границей по площади |
| Попытки | Число проверок пересечения конкретного положения с доской |
| Откаты | Число снятий реально размещённой фигуры после неудачной ветви |
| Время | `time.Since` от начала до конца вызова решателя |

Проверки положений при выборе наиболее ограниченной группы тоже считаются
попытками. Уже проверенное положение ставится без повторного счёта. Счётчики
накапливаются по всем проверенным размерам. Время включает подготовку поиска и
вызовы визуализатора, но не чтение входного файла и печать итогового отчёта.
Сравнивать скорость лучше без `--visualize`: терминальный вывод имеет свою цену.

Анализатор проверяет целостность буквенных фигур и отвергает ошибочную сетку.
Квадрат может быть больше нижней границы по площади из-за геометрии фигур — это
не означает ошибку поиска. Например, для четырёх S в `goodexample01` нужно 5×5,
хотя площадь даёт границу 4×4.

Визуализатор подписан на реальные события решателя, печатает доску после каждой
установки и каждого снятия фигуры и текущие счётчики. Пример с откатами:

```sh
./bin/tetris-visualizer testdata/rotation-demo.txt --fixed --analyze
```

## Проверка и аудит

```sh
go test ./...      # Модульные тесты и независимый перебор малых наборов
make check        # Формат, vet, race detector, тесты и аудит бинарников
make fuzz         # По 10 секунд fuzzing парсера и решателя
make bench        # Измерения времени и выделений памяти
```

CI выполняет `make check` и `make fuzz` на Linux с Go 1.25 и 1.27.
Исходный код приложения не требует внешних модулей; `go.sum` не нужен.
Два файла `main.go` — тонкие точки входа, проверяемые запуском бинарников.

Сопоставление с пунктами ТЗ: [`docs/AUDIT.md`](docs/AUDIT.md).
Измеренные результаты и пределы проверок: [`docs/VALIDATION.md`](docs/VALIDATION.md).
Объяснение алгоритма и вопросы для подготовки: [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).

```text
cmd/tetris-optimizer/   обычная команда
cmd/tetris-visualizer/  бонусная команда
internal/parser/       чтение и проверка входных данных
internal/tetromino/    геометрия и повороты
internal/solver/       точный поиск и его счётчики
internal/analyzer/     проверка результата и метрики

internal/cli/          общие флаги, ошибки и сигналы
testdata/              официальные и дополнительные примеры
scripts/audit.py       проверка исполняемых файлов извне
```
